<

>
    vim.lsp.config("*", {
      capabilities = require("completion-tools").get_lsp_capabilities(),
    })

                                                        *completion-tools-api*
The module is available as "completion-tools" and "completion_tools".

setup(opts)              Configure providers, mappings and autocmds.
show(opts?)              Request completions, optionally with opts.sources.
hide()                   Hide menu and documentation, cancel pending work.
is_menu_visible()        Return whether the floating menu is visible.
accept(opts?)            Apply selected item; opts.mode="insert" or "replace".
accept_word()            Accept the next word of a Copilot suggestion.
accept_line()            Accept the next line of a Copilot suggestion.
select_next(opts?)       Move selection; opts.count defaults to 1.
select_prev(opts?)       Move selection backwards.
get_items()              Return current CompletionItems (read-only).
get_selected_item()      Return the selected CompletionItem or nil.
get_context()            Return current request context (read-only).
get_status()             Return a detached runtime diagnostic snapshot.
show_status()            Print and return the diagnostic snapshot.
show_documentation()     Resolve/show selected item documentation.
scroll_documentation_up()
scroll_documentation_down()
snippet_forward()
snippet_backward()
get_lsp_capabilities(base?)
register_source(id, source)
refresh_keymaps()         Reinstall mappings after lazy dependencies change them.
refresh_cmdline()         Refresh an existing external command-line menu.
dispose()                Release resources and restore owned keymaps.

:CompletionToolsStatus prints engine/source status after setup. get_status()
reports readiness, stale retained frames, last request reason and per-source
status, elapsed_ms, raw_count, shown_count, requests, cache_hits, responses,
timeouts, errors and last_error. Counters reset on setup. Cache hits exclude
provider requests; timings include async waiting/processing, not terminal drawing.
Raw counts follow transforms and precede quotas/deduplication; shown counts are
current menu contributions. Callback errors survive later successful requests.
:checkhealth completion-tools includes status, deadlines and missing sources.

accept.mode="replace" is the default. "insert" preserves suffix text using an
InsertReplaceEdit's insert range. accept({mode="insert"}) overrides one action.
Ordinary TextEdit ranges are unchanged. LSP insertTextMode=1 preserves whitespace;
2 adjusts continuation indentation. The advertised LSP default is 2. Native
snippets and LuaSnip retain placeholders without double indentation.
Custom snippets.expand(text, options) receives adjusted text and
{insert_text_mode?, indentation, bufnr}; disable engine indentation when a mode
is present. Non-LSP items without a mode keep their previous behavior.

                                                       *completion-tools-keys*
CTRL-Space   Show completions or documentation.
CTRL-N/P     Select next/previous item, without inserting it.
CTRL-Y       Accept the selected item.
<Tab>        Accept, jump forward in a snippet, or fall back.
<S-Tab>      Jump backwards in a snippet, or fall back.
CTRL-E       Hide, or fall back.
<CR>         Unchanged by default.

keymap={} installs no insert/select mappings; cmdline.keymap={} disables command
line mappings. Both custom keymaps replace their respective defaults.
Actions can be method names, functions or "fallback".
Buffer-local mappings take precedence over global plugin mappings.

                                                   *completion-tools-triggers*
Insert-mode automatic completion opens for words and trigger_characters={"."}.
Other symbols/whitespace close the menu and cancel pending requests, even when
advertised as LSP triggers or min_keyword_length=0. Manual show() bypasses this
filter. Command-line completion is independent.
trigger_characters also accepts function(ctx) -> string[] for filetype rules:
>
    trigger_characters = function(ctx)
      return ctx.filetype == "tex" and { ".", "\\", "{" } or { "." }
    end
<
An empty list disables symbol triggers; words still complete. Add "/" to open
path completion immediately after a slash.

                                                   *completion-tools-ranking*
Optional ranking (all disabled by default):
>
    ranking = {
      history = { enabled = true, max_entries = 1000 },
      proximity = { enabled = true, lines = 50 },
      max_typos = 1,
    }
<
History combines frequency/recency, scoped by source and filetype. It persists
under stdpath("state")/completion-tools/history.json; history.path overrides it.
Records are bounded and saved after 500 ms idle or on dispose/exit. Proximity
weights words within the configured line radius. Bonuses preserve match tiers.
Typos are opt-in (0 or 1), ASCII-only prefixes of 4-32 characters, and rank below
literal matches. Command-line matching/order is unaffected.

                                                     *completion-tools-sources*
Built-ins: lsp, path, buffer, snippets; optional Ex cmdline.
Opt-in sources: dictionary, spell, copilot. All are independent of Blink.
snippets.preset="luasnip" enables the optional literal-trigger LuaSnip adapter.
cmdline.enabled=true enables command/search completion; see below.

Global timeout_ms=2000 bounds pending async requests; 0 disables the deadline.
providers[id].timeout_ms overrides it. Timeouts cancel requests, reject late
results, and keep already received partial candidates.
providers[id].max_items caps matched/ranked candidates before global merging.
providers[id].fallback_for={"lsp"} waits for all named sources to finish without
matches. Disabled/unselected sources count as empty. Chains are supported;
cycles are rejected. Timeouts/errors can release fallback sources. Synchronous
Lua callbacks and native getcompletion() cannot be interrupted by deadlines.

                                                   *completion-tools-copilot*
Add "copilot" to sources. Install GitHub's official Copilot Language Server:
>
    npm install -g @github/copilot-language-server
<
No copilot.lua dependency or chat UI is needed. Remove its plugin specification
and require("copilot").setup() when migrating.
>
    require("completion-tools").setup({
      sources = { "copilot", "lsp", "path", "buffer", "snippets" },
      copilot = {
        command = { "copilot-language-server", "--stdio" },
        debounce_ms = 150, max_items = 3, show_status = true,
        filetypes = {}, settings = {},
      },
    })
<
:CompletionToolsCopilot auth       Display device code and open GitHub login.
:CompletionToolsCopilot status     Inspect the native client and errors.
:CompletionToolsCopilot disable    Disable globally and detach buffers.
:CompletionToolsCopilot enable     Enable again.
:CompletionToolsCopilot restart    Stop; restart on the next request.
:CompletionToolsCopilot signout    Sign out through the official server.

The server starts on demand. Normal listed buffers are eligible by default.
filetypes={markdown=false} excludes Markdown; ["*"]=false excludes unlisted
filetypes. should_attach(bufnr) may further restrict attachment. command is a
complete argv list; use an absolute executable path for Mason outside PATH.
settings are forwarded to the server (e.g. http.proxy). The server manages
credentials; GitHub Copilot access is required.
root_dir accepts a directory or function(bufnr); defaults to the nearest .git or
cwd. Each eligible project's root is registered with the shared server, plus any
workspace_folders directories. Canonical paths are deduplicated. Language IDs
normalize common Neovim filetypes; language_ids maps filetype names to overrides.
Renames and first saves close the old URI before opening the new document.
accept_word/accept_line keep the selected suggestion's remainder without another
request. They require a literal continuation and return false for other sources.
No keys are assigned by default; use these action names in keymap chains.
New requests debounce independently and cancel on edits/hide/dispose. Completed
suggestions are reused immediately during exact forward typing on the same line,
including matching spaces/punctuation. Matching candidates stay selectable and
their UTF-16 ranges are updated without another request. A miss uses the normal
trigger rules and debounce. Deletion, newline, cursor movement, other edits,
hiding or leaving the buffer/window/insert mode invalidate the cache.
request_mode="cycling" is the default. Optional "staged" publishes getCompletions
results first, then fills up to max_items via getCompletionsCycling. First-stage
choices remain usable and their identities survive merging. Matching input reuses
them and cancels alternatives. A second-stage error retains the first choices.
This mode may use two requests per snapshot; latency benefits depend on the server.
Cycling requests retain up to max_items unique edits (default 3); the service may
return fewer. Copilot fields are purple (#cba6f7) through CompletionToolsCopilot.
The first nonempty line appears in the menu, with full insertion in docs.
UTF-16 ranges and multiline literal edits are preserved; acceptance is reported.
There is no Copilot source in command-line mode.
show_status=true displays Copilot icons in the completion window footer:
 ready (muted when no suggestions),  disabled,  warning/unavailable,  sign-in
required. Waiting/startup/generation show  with an animated dots spinner (80 ms).
Animation stops on completion/hide/dispose and changes only the border. The menu
opens only when actual candidates exist; waiting or empty results never open a
status-only window. Icons cannot be selected/accepted; notifications preserve
selection and never reopen a dismissed menu. Set
show_status=false to hide the footer.
Attached buffers sync full contents on open, then incremental edits. Requests
identify the document/version/cursor; the local server can use both sides of the
cursor. The official server prepares the cloud prompt; the current keyword only
controls triggering/filtering, not the transmitted document context.

                                                   *completion-tools-cmdline*
cmdline = { enabled=false, auto_show=true, fuzzy=true, min_keyword_length=1,
            types={":","/","?"} }

Ex uses native getcompletion() (including custom user-command completions);
search uses buffer words. Native order, wildcards and escaped paths are retained.
fuzzy=true temporarily enables native fuzzy matching for Ex completion and
restores 'wildoptions' even after errors. Set fuzzy=false to follow your existing
'wildoptions'. File/directory names still use native wildcard expansion.
Custom completers follow native semantics.
Acceptance preserves modifiers, option prefixes, namespaces and trailing text.
Empty command lines stay closed; empty arguments after a command may complete.

Independent cmdline.keymap defaults:
CTRL-Space opens; Up/Down and CTRL-P/N select without inserting; Tab accepts or
opens; Shift-Tab selects backwards or opens. Enter retains native execution/
search confirmation. Native wildmenu/popupmenu and unsupported input() prompts
retain their existing keys. Shell commands and backtick expansion are excluded.
auto_show=false uses manual triggers; types={":"} enables only Ex.
Use both InsertEnter and CmdlineEnter lazy-loading events.

cmdline.get_anchor(ctx) may return {row,col,height}, describing an external
command-line's entire outer frame in zero-based screen cells, including borders.
The menu avoids that frame and flips above when necessary. External renderers
call refresh_cmdline() after geometry changes; idle menus never open from it.
No renderer subscription or Blink adapter is required by the core.
Commands, help tags, options and paths use uniform kind coloring plus match
emphasis. Words/punctuation in their names are not interpreted as source code.
Lua and Vim expression/function completions use Lua/Vim syntax respectively,
independent of the current buffer's filetype. Kind/source columns follow themes.
Override CompletionToolsKindReference for help tags, or return scoped spans from
menu.highlight.custom using ctx.mode=="cmdline" and ctx.completion_type.
The native getcompletion API is synchronous: slow custom callbacks/filesystems
can still block, as with native completion.

Source functions use dot calls:
>
    complete(ctx, callback) -> cancel?
    resolve(entry, callback) -> cancel?  -- optional
    execute(entry, ctx)                  -- optional, after primary edit
    trigger(ctx) -> boolean              -- optional
    reuse(ctx, response, previous_ctx) -> response? -- optional, validated reuse
    dispose()                           -- optional
<
complete callbacks receive {items, start_col?, reusable?, is_incomplete?, pending?, stable?}.
start_col is a zero-based byte column; item TextEdits take precedence.
LSP clients carry their negotiated encoding; custom edits default to UTF-8.
resolve callbacks receive a CompletionItem.
Set source.resolve_on_accept=false for documentation-only resolvers; the default
also resolves after acceptance for delayed edits/commands.
Entry fields: item, context, start_col, source_id.

Callbacks may publish more than once. Stale results are ignored even if a
provider does not honour cancellation. The provider owns external resources.
Set pending=true while more results are expected; omit or clear it on the final
response. Only complete, non-pending reusable lists are cached for forward typing.
For generated edits, reuse may validate each candidate and return an updated
response, or nil to discard the cache and use normal completion. Final responses
and pending lists explicitly marked stable=true qualify. Same-snapshot reuse of
a pending list must return nil so complete re-subscribes to the remaining results.
This cache allows uninterrupted same-line insertions at the
last cursor and clears on hide. Validated candidates may continue through blocked
characters without starting other sources there; reusable=true is independent.
During typing/backspace within one keyword, the previous menu remains visible
until matching results arrive or all sources finish without matches. Stale items
cannot be accepted. Empty input/context changes close the old menu immediately.
The retained menu follows the cursor; documentation stays for the same selection.
Background refreshes preserve a manually opened session and show({sources=...})
overrides at the same input snapshot, including LSP attach/detach. New edits
follow ordinary automatic trigger rules. A delayed TextChangedI for text already
included in show() does not restart or dismiss that manual request.
Automatic preselection follows the first item of each updated ranking. Navigation
via select_next/select_prev marks a manual selection, preserved by identity during
same-context refreshes. If it disappears, selection/docs are cleared and accept()
returns false; later updates do not automatically reselect even if it reappears.
Navigate again to choose an item. Typing/backspace reset to the configured
preselect behavior; preselect=false continues to leave items unselected.
select_next/select_prev accept {count=1, wrap=true}. Set wrap=false for paging:
the selection stops at the first/last item and still returns true at the boundary
so a mapped paging key is consumed rather than running its fallback action.

                                                *completion-tools-dictionary*
Add "dictionary" to sources, and configure dictionary.files (list or function).
UTF-8, one word/phrase per line; CRLF/BOM and duplicate lines are supported.
Defaults: min_keyword_length=3, max_items=10, matching="fuzzy", capitalize=true,
max_bytes=16777216, max_words=500000, max_word_bytes=256, timeout_ms=5000.
dictionary.documentation defaults to {enabled=true, command="wn", timeout_ms=1500}.
Selected items resolve English WordNet meanings via {command, original_word, "-over"}
asynchronously. command may be an executable path. No network or Blink dependency.
Missing tools, unknown words and failures leave ordinary completion available.
Original dictionary spelling is used even for capitalized display/insert text.
Selection/input changes, acceptance, hide and disposal cancel obsolete queries.
At most 128 successful/empty lookups are cached, each retaining up to 64 KiB text.
Set enabled=false to disable meanings; WordNet does not supply Chinese translations.
matching="prefix" uses prefix buckets; "fuzzy" scores subsequences.
File changes invalidate the background index. Lists replace rather than merge.
At most four indexes / 64 cached queries per index; warnings for missing files
and truncated budgets are deduplicated. Files exceeding the remaining byte
budget are skipped.

                                                     *completion-tools-spell*
Add "spell" to sources. Only active with window-local 'spell' enabled.
Inherits native spelllang/spellfile/spellcapcheck/spelloptions/spellsuggest.
Defaults: min_keyword_length=2, max_items=3, debounce_ms=60, timeout_ms=5000,
sort="match", preselect_current_word=true, suggest_when_correct=false.
sort="match" prioritizes fuzzy matches and keeps non-matching corrections last.
sort="suggestion" preserves native spellsuggest() ordering.
enable_in_context(ctx) can further restrict the source.
Compiled personal word-list updates reload the worker. User-init functions
referenced by spellsuggest=expr:... are not copied to the worker.

Both word sources return Text candidates. They run in separate, persistent,
on-demand headless Neovim processes; no user init is loaded. At most one active
and one latest pending request are retained. dispose/setup/exit stop workers.
Slow results cannot block main-thread typing or publish after cancellation.

                                                      *CompletionToolsAccept*
User CompletionToolsAccept fires after primary acceptance.
args.data contains item, source, bufnr and optional client_id.
Private item fields (leading underscore) are omitted from event data.
If LSP resolve finishes late, additional edits are applied only when the
accepted buffer's changedtick has not changed since primary insertion.

                                                    *completion-tools-highlight*
CompletionToolsMenu       CompletionToolsBorder     CompletionToolsSelected
CompletionToolsMatch      CompletionToolsSource     CompletionToolsDoc
CompletionToolsDeprecated CompletionToolsKind{LSP kind name}
CompletionToolsDocCode
CompletionToolsDocItalic   CompletionToolsDocBold     CompletionToolsDocBoldItalic
CompletionToolsDocSeparator

Snippet icons/labels/kind names use CompletionToolsKindSnippet, linked to Special
by default. Documentation hides Markdown code fences and inline-code backticks,
preserving code text, indentation and syntax highlighting. Detail and plaintext
documentation remain literal. Inline code uses CompletionToolsDocCode (String).
Prose emphasis uses local conceal for italic, bold and combined styles, with
the corresponding DocItalic/DocBold/DocBoldItalic groups. Thematic rules (three
or more dashes, asterisks or underscores) use full-width DocSeparator lines.
Code spans/blocks remain literal. Sizing accounts for raw-column conceal wrapping.
Documentation reuses lexical/Tree-sitter options, without menu custom callbacks.

                                                       *completion-tools-menu*
Default columns: { {"kind_icon"}, {"label", gap=1}, {"kind"}, {"source"} }.
Components: kind_icon, label, kind, source, label_detail, label_description.
Source names: LSP, Buffer, Path, Snippets, Cmdline, Dict, Spell.
Custom sources retain their IDs.
menu.columns replaces the entire column list. column_gap and padding default
to 1. kind_icons=false hides icons; a name-to-icon table overrides defaults.
label_details=false separates the label from LSP detail/description fields.
Display text never changes the accepted CompletionItem.
With label_details=true, descriptions use an automatically aligned auxiliary
column unless label_description is explicitly positioned in menu.columns.
File/folder paths are muted location metadata, shortened relative to the current
directory or home; clipping keeps the distinguishing end of the path. Metadata
gives up excess width before candidate labels. Full detail, labelDetails.detail
and labelDetails.description remain available in the wrapping documentation
window (automatically, or with show_documentation); paths there are literal.

Independent label highlighting uses kind groups, a lexical fallback and optional
native Tree-sitter highlights queries. No colorful-menu or Blink dependency.
menu.highlight: enabled=true, treesitter=true, max_bytes=1024, cache_size=512.
Only visible rows are highlighted; plain words do not create parsers.
File/folder candidates retain kind and match emphasis without code syntax colors.
Missing parsers/queries and incomplete signatures keep the lexical fallback.
Pending sources retain their matching candidates until useful/final results or
the deadline, so a fast source's new results do not briefly remove slower sources.
Retained candidates cannot be resolved or accepted; fresh candidates remain usable.
menu.update_interval_ms=16 combines results within a fixed interval after the
previous publication, including across rapid edits. The first useful result when
opening the menu is immediate; continuous input/streaming cannot postpone updates.
Set to 0 to publish every event-loop batch. Navigation/acceptance use displayed
candidates without this delay. Width and column allocations are retained until
the menu closes, growing into spare space without shrinking for shorter results.
New metadata may be truncated to preserve existing columns. A smaller editor may
reclaim space. Unchanged rows/highlights are preserved on redraw.
menu.shrink_delay_ms=50 delays height reduction after results are published.
Input/results reset the delay; growth is immediate. Extra rows are
blank and unselectable. Set to 0 for immediate shrinking. The opening direction
uses menu.max_height (default 12), independent of current result count: below
when it fits, otherwise the side with more space (ties prefer below). Input
movement/resize recalculates placement. Final empty results close when published.

menu.inverse="auto" reverses menus above the input by default, keeping the
first-ranked item nearest the input. Set true to always reverse, false to always
use top-to-bottom order. This applies to Insert and command-line completion.
Ranking, preselection and acceptance are unchanged; get_items() stays ranked.
select_next/select_prev always move down/up on screen, including reversed menus.
Paging and boundary clamping use the same screen directions.
Retained blank rows appear opposite the first-ranked candidate.

menu.max_label_bytes=1024 bounds each displayed field. Default icons need a
Nerd Font. Unknown kinds use CompletionToolsKindUnknown.

menu.highlight.custom(entry, ctx, text) may return extra spans:
    { {start_byte, end_byte, "HighlightGroup", priority?}, ... }
Ranges are zero-based/exclusive bytes; default priority is 190.
Ranges are clipped and checked for UTF-8 boundaries. Do not mutate entries.
Match emphasis (200) and deprecation (210) retain syntax/selection colors.
