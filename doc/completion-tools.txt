                                                        *completion-tools-api*
The module is available as "completion-tools" and "completion_tools".

setup(opts)              Configure providers, mappings and autocmds.
show(opts?)              Request completions, optionally with opts.sources.
hide()                   Hide menu and documentation, cancel pending work.
is_menu_visible()        Return whether the floating menu is visible.
accept()                 Apply selected item; false for stale/no selection.
select_next(opts?)       Move selection; opts.count defaults to 1.
select_prev(opts?)       Move selection backwards.
get_items()              Return current CompletionItems (read-only).
get_selected_item()      Return the selected CompletionItem or nil.
get_context()            Return current request context (read-only).
show_documentation()     Resolve/show selected item documentation.
scroll_documentation_up()
scroll_documentation_down()
snippet_forward()
snippet_backward()
get_lsp_capabilities(base?)
register_source(id, source)
refresh_keymaps()         Reinstall mappings after lazy dependencies change them.
refresh_cmdline()         Refresh an existing external command-line menu.
dispose()                Release resources and restore owned keymaps.

                                                       *completion-tools-keys*
CTRL-Space   Show completions or documentation.
CTRL-N/P     Select next/previous item, without inserting it.
CTRL-Y       Accept the selected item.
<Tab>        Accept, jump forward in a snippet, or fall back.
<S-Tab>      Jump backwards in a snippet, or fall back.
CTRL-E       Hide, or fall back.
<CR>         Unchanged by default.

keymap={} installs no insert/select mappings; cmdline.keymap={} disables command
line mappings. Both custom keymaps replace their respective defaults.
Actions can be method names, functions or "fallback".
Buffer-local mappings take precedence over global plugin mappings.

                                                     *completion-tools-sources*
Built-ins: lsp, path, buffer, snippets; optional Ex cmdline.
Opt-in sources: dictionary, spell. Both are independent of Blink.
snippets.preset="luasnip" enables the optional literal-trigger LuaSnip adapter.
cmdline.enabled=true enables command/search completion; see below.

                                                   *completion-tools-cmdline*
cmdline = { enabled=false, auto_show=true, min_keyword_length=1,
            types={":","/","?"} }

Ex uses native getcompletion() (including custom user-command completions);
search uses buffer words. Native order, wildcards and escaped paths are retained.
Acceptance preserves modifiers, option prefixes, namespaces and trailing text.
Empty command lines stay closed; empty arguments after a command may complete.

Independent cmdline.keymap defaults:
CTRL-Space opens; Up/Down and CTRL-P/N select without inserting; Tab accepts or
opens; Shift-Tab selects backwards or opens. Enter retains native execution/
search confirmation. Native wildmenu/popupmenu and unsupported input() prompts
retain their existing keys. Shell commands and backtick expansion are excluded.
auto_show=false uses manual triggers; types={":"} enables only Ex.
Use both InsertEnter and CmdlineEnter lazy-loading events.

cmdline.get_anchor(ctx) may return {row,col,height}, describing an external
command-line's entire outer frame in zero-based screen cells, including borders.
The menu avoids that frame and flips above when necessary. External renderers
call refresh_cmdline() after geometry changes; idle menus never open from it.
No renderer subscription or Blink adapter is required by the core.
Commands, help tags, options and paths use uniform kind coloring plus match
emphasis. Words/punctuation in their names are not interpreted as source code.
Lua and Vim expression/function completions use Lua/Vim syntax respectively,
independent of the current buffer's filetype. Kind/source columns follow themes.
Override CompletionToolsKindReference for help tags, or return scoped spans from
menu.highlight.custom using ctx.mode=="cmdline" and ctx.completion_type.
The native getcompletion API is synchronous: slow custom callbacks/filesystems
can still block, as with native completion.

Source functions use dot calls:
>
    complete(ctx, callback) -> cancel?
    resolve(entry, callback) -> cancel?  -- optional
    execute(entry, ctx)                  -- optional, after primary edit
    trigger(ctx) -> boolean              -- optional
    dispose()                           -- optional
<
complete callbacks receive {items, start_col?, reusable?, is_incomplete?, pending?}.
start_col is a zero-based byte column; item TextEdits take precedence.
LSP clients carry their negotiated encoding; custom edits default to UTF-8.
resolve callbacks receive a CompletionItem.
Set source.resolve_on_accept=false for documentation-only resolvers; the default
also resolves after acceptance for delayed edits/commands.
Entry fields: item, context, start_col, source_id.

Callbacks may publish more than once. Stale results are ignored even if a
provider does not honour cancellation. The provider owns external resources.
Set pending=true while more results are expected; omit or clear it on the final
response. Only complete, non-pending reusable lists are cached for forward typing.
During typing/backspace within one keyword, the previous menu remains visible
until matching results arrive or all sources finish without matches. Stale items
cannot be accepted. Empty input/context changes close the old menu immediately.
The retained menu follows the cursor; documentation stays for the same selection.

                                                *completion-tools-dictionary*
Add "dictionary" to sources, and configure dictionary.files (list or function).
UTF-8, one word/phrase per line; CRLF/BOM and duplicate lines are supported.
Defaults: min_keyword_length=3, max_items=10, matching="fuzzy", capitalize=true,
max_bytes=16777216, max_words=500000, max_word_bytes=256, timeout_ms=5000.
dictionary.documentation defaults to {enabled=true, command="wn", timeout_ms=1500}.
Selected items resolve English WordNet meanings via {command, original_word, "-over"}
asynchronously. command may be an executable path. No network or Blink dependency.
Missing tools, unknown words and failures leave ordinary completion available.
Original dictionary spelling is used even for capitalized display/insert text.
Selection/input changes, acceptance, hide and disposal cancel obsolete queries.
At most 128 successful/empty lookups are cached, each retaining up to 64 KiB text.
Set enabled=false to disable meanings; WordNet does not supply Chinese translations.
matching="prefix" uses prefix buckets; "fuzzy" scores subsequences.
File changes invalidate the background index. Lists replace rather than merge.
At most four indexes / 64 cached queries per index; warnings for missing files
and truncated budgets are deduplicated. Files exceeding the remaining byte
budget are skipped.

                                                     *completion-tools-spell*
Add "spell" to sources. Only active with window-local 'spell' enabled.
Inherits native spelllang/spellfile/spellcapcheck/spelloptions/spellsuggest.
Defaults: min_keyword_length=2, max_items=3, debounce_ms=60, timeout_ms=5000,
sort="match", preselect_current_word=true, suggest_when_correct=false.
sort="match" prioritizes fuzzy matches and keeps non-matching corrections last.
sort="suggestion" preserves native spellsuggest() ordering.
enable_in_context(ctx) can further restrict the source.
Compiled personal word-list updates reload the worker. User-init functions
referenced by spellsuggest=expr:... are not copied to the worker.

Both word sources return Text candidates. They run in separate, persistent,
on-demand headless Neovim processes; no user init is loaded. At most one active
and one latest pending request are retained. dispose/setup/exit stop workers.
Slow results cannot block main-thread typing or publish after cancellation.

                                                      *CompletionToolsAccept*
User CompletionToolsAccept fires after primary acceptance.
args.data contains item, source, bufnr and optional client_id.
Private item fields (leading underscore) are omitted from event data.
If LSP resolve finishes late, additional edits are applied only when the
accepted buffer's changedtick has not changed since primary insertion.

                                                    *completion-tools-highlight*
CompletionToolsMenu       CompletionToolsBorder     CompletionToolsSelected
CompletionToolsMatch      CompletionToolsSource     CompletionToolsDoc
CompletionToolsDeprecated CompletionToolsKind{LSP kind name}
CompletionToolsDocCode

Snippet icons/labels/kind names use CompletionToolsKindSnippet, linked to Special
by default. Documentation hides Markdown code fences and inline-code backticks,
preserving code text, indentation and syntax highlighting. Detail and plaintext
documentation remain literal. Inline code uses CompletionToolsDocCode (String).
Documentation reuses lexical/Tree-sitter options, without menu custom callbacks.

                                                       *completion-tools-menu*
Default columns: { {"kind_icon"}, {"label", gap=1}, {"kind"}, {"source"} }.
Components: kind_icon, label, kind, source, label_detail, label_description.
Source names: LSP, Buffer, Path, Snippets, Cmdline, Dict, Spell.
Custom sources retain their IDs.
menu.columns replaces the entire column list. column_gap and padding default
to 1. kind_icons=false hides icons; a name-to-icon table overrides defaults.
label_details=false separates the label from LSP detail/description fields.
Display text never changes the accepted CompletionItem.

Independent label highlighting uses kind groups, a lexical fallback and optional
native Tree-sitter highlights queries. No colorful-menu or Blink dependency.
menu.highlight: enabled=true, treesitter=true, max_bytes=1024, cache_size=512.
Only visible rows are highlighted; plain words do not create parsers.
Missing parsers/queries and incomplete signatures keep the lexical fallback.
menu.max_label_bytes=1024 bounds each displayed field. Default icons need a
Nerd Font. Unknown kinds use CompletionToolsKindUnknown.

menu.highlight.custom(entry, ctx, text) may return extra spans:
    { {start_byte, end_byte, "HighlightGroup", priority?}, ... }
Ranges are zero-based/exclusive bytes; default priority is 190.
Ranges are clipped and checked for UTF-8 boundaries. Do not mutate entries.
Match emphasis (200) and deprecation (210) retain syntax/selection colors.
